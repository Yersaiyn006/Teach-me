
# Teach Me

Teach Me — оқу мәтінінен сұрақ-жауап карточкаларын автоматты түрде жасайтын Django веб-қосымшасы.

Жобаның мақсаты — студентке оқу материалын меңгеруге, негізгі ақпаратты қайталауға және өзін-өзі тексеруге көмектесу.

Пайдаланушы тақырып пен оқу мәтінін енгізеді. Қосымша мәтін негізінде карточкалар жасайды, оларды SQLite дерекқорына сақтайды және кейін қайта ашуға мүмкіндік береді.

## 1. Жобаның мүмкіндіктері

- Оқу мәтінін енгізу (80–12000 таңба).
- Материал тақырыбын көрсету (120 таңбаға дейін).
- Бір материалдан 3–8 сұрақ-жауап карточкасын жасау.
- Карточкада сұрақ, жауап және бастапқы мәтіннен дәйексөз көрсету.
- Жауапты «Жауапты көрсету» элементі арқылы ашу және жабу.
- Материалдар мен карточкаларды SQLite дерекқорына сақтау.
- Сақталған материалдарды жеке URL арқылы қайта ашу.
- Генерация нәтижесін серверде тексеру.
- Сақтау кезінде транзакцияны пайдалану.
- DEMO және optional LIVE режимдерін қолдау.

Жобада пайдаланушыны тіркеу, авторизация және материал иесін анықтау механизмі қарастырылмаған.

## 2. Қолданылатын технологиялар

- Python
- Django 5.2
- SQLite
- HTML, CSS, JavaScript
- python-dotenv
- Gemini API (тек LIVE режимінде)

`requirements.txt`:

```text
Django>=5.2,<5.3
python-dotenv>=1.1,<2
```

LIVE режимінде Gemini API-ге сұраныс Python стандартты кітапханасының `urllib` модулі арқылы жіберіледі. Бөлек Gemini SDK тәуелділігі көрсетілмеген.

## 3. Жобаны орнату

Алдымен Python орнатылған болуы керек.

Командаларды `manage.py` және `requirements.txt` орналасқан жобаның негізгі бумасында орындау қажет.

### Windows (PowerShell)

Виртуалды орта жасау:

```powershell
python -m venv .venv
```

Виртуалды ортаны іске қосу:

```powershell
.\.venv\Scripts\Activate.ps1
```

Егер PowerShell іске қосуға рұқсат бермесе, виртуалды ортаның Python интерпретаторын тікелей қолдануға болады:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Белсендірілген виртуалды ортада тәуелділіктерді орнату:

```powershell
python -m pip install -r requirements.txt
```

### macOS

Виртуалды орта жасау:

```bash
python3 -m venv .venv
```

Ортаны белсендіру:

```bash
source .venv/bin/activate
```

Тәуелділіктерді орнату:

```bash
python -m pip install -r requirements.txt
```

## 4. Орта параметрлері

Жобаның негізгі бумасында `.env` файлы қолданылады.

Мысал конфигурация:

```dotenv
TEACHME_MODE=demo
GEMINI_API_KEY=
GEMINI_MODEL=
GEMINI_TIMEOUT_SECONDS=25
```

Жұмыс режимдері:

- `demo` — дайын мысал негізінде генерация.
- `live` — Gemini API арқылы генерация.

`.env` файлына API кілті сияқты құпия ақпарат енгізілуі мүмкін.

**Маңызды:** `.env` файлын Git репозиторийіне жарияламау керек. Оны `.gitignore` файлына қосу қажет.

Құпия кілттерді README, скриншот немесе ашық репозиторий ішінде көрсетуге болмайды.

Құпия ақпаратсыз үлгі конфигурацияны `.env.example` файлында сақтауға болады.

## 5. Дерекқорды дайындау

Жоба SQLite дерекқорын қолданады.

Модельдер:

**Source**

Оқу материалы туралы ақпаратты сақтайды:

- `title` — материал тақырыбы;
- `text` — бастапқы оқу мәтіні;
- `created_at` — жасалған уақыты;
- `generation_mode` — генерация режимі.

**Flashcard**

Оқу карточкасын сақтайды:

- `source` — материалға байланыс;
- `position` — карточканың реттік нөмірі;
- `question` — сұрақ;
- `answer` — жауап;
- `source_quote` — бастапқы мәтіннен алынған үзінді.

Бір Source бірнеше Flashcard жазбасымен байланыса алады.

Дерекқор миграцияларын қолдану:

```bash
python manage.py migrate
```

Егер модельдерге жаңа өзгеріс енгізілсе, миграция файлын жасау қажет болуы мүмкін:

```bash
python manage.py makemigrations study
```

Миграциялардың жағдайын тексеру үшін:

```bash
python manage.py makemigrations --check --dry-run
```

Бұл тексеру командасы жаңа миграция файлын жасамайды.

## 6. Серверді іске қосу

```bash
python manage.py runserver 127.0.0.1:8000
```

Браузерден ашу:

http://127.0.0.1:8000/

Бұл — жергілікті әзірлеу сервері. Оны дайын production сервері ретінде пайдалануға болмайды.

## 7. DEMO режимі

DEMO режимі жобаны интернетке немесе Gemini API-ге қосылмай көрсетуге арналған.

`.env` параметрі:

```dotenv
TEACHME_MODE=demo
```

DEMO режимінде қосымша тек жоба ішінде алдын ала дайындалған оқу мәтінін қабылдайды.

Дайын мысал тақырыбы — компьютерлік желілер.

Осы мәтін бойынша **тұрақты 3 карточка** қайтарылады.

DEMO режимінің ерекшеліктері:

1. Генерация үшін сыртқы AI сервисі шақырылмайды.
2. Дайын мысал мәтіні өзгертілсе, генерация қабылданбайды.
3. Нәтиже серверлік валидациядан өтеді.
4. Сәтті нәтиже дерекқорға сақталады.
5. Пайдаланушы сақталған карточкаларды кейін қайта аша алады.

DEMO режимі кез келген жаңа мәтінге AI генерациясын жасамайды.

## 8. LIVE режимі (optional)

LIVE режимі Gemini API арқылы жаңа оқу мәтіндерінен карточкалар жасауға арналған.

Мысал конфигурация:

```dotenv
TEACHME_MODE=live
GEMINI_API_KEY=YOUR_API_KEY
GEMINI_MODEL=YOUR_AVAILABLE_MODEL_ID
GEMINI_TIMEOUT_SECONDS=25
```

Параметрлер:

| Параметр | Мақсаты |
|---|---|
| `TEACHME_MODE` | `demo` немесе `live` режимін таңдау |
| `GEMINI_API_KEY` | Gemini API кілті |
| `GEMINI_MODEL` | Қолжетімді модель идентификаторы |
| `GEMINI_TIMEOUT_SECONDS` | Сұраныстың күту уақыты |

LIVE режимінде:

1. Пайдаланушы оқу мәтінін енгізеді.
2. Сервер Gemini API-ге сұраныс жібереді.
3. Жауап құрылымдық тексеруден өтеді.
4. Қабылданған карточкалар дерекқорға сақталады.
5. Пайдаланушы материалдың жеке бетіне бағытталады.

API кілті, модель атауы немесе байланыс дұрыс болмаса, генерация қатемен аяқталуы мүмкін.

**LIVE режимінің нақты жұмыс істегені осы README үшін берілген терминал нәтижелерімен расталмаған.**

## 9. Карточкаларды тексеру

Генерация нәтижесінде әр карточкада үш міндетті өріс болады:

```json
{
  "question": "Сұрақ",
  "answer": "Жауап",
  "source_quote": "Бастапқы мәтіндегі нақты үзінді"
}
```

Валидация ережелері:

- Карточка саны 3–8 аралығында болуы керек.
- Барлық міндетті өрістер болуы қажет.
- Өрістер бос болмауы керек.
- Сұрақтар қайталанбауы тиіс.
- Сұрақ ұзындығы 300 таңбадан аспайды.
- Жауап және дәйексөз 1600 таңбадан аспайды.
- `source_quote` бастапқы мәтінде дәл сол күйінде кездесуі керек.

Егер бір карточка жарамсыз болса, бүкіл генерация нәтижесі қабылданбайды.

### Дәйексөз тексеруінің шектеуі

`source_quote` тексеруі дәйексөздің бастапқы мәтінде бар екенін анықтайды.

Бірақ бұл тексеру:

- жауаптың ғылыми немесе фактілік дұрыстығын;
- жауап пен дәйексөз арасындағы мағыналық байланысты;
- бастапқы мәтіндегі ақпараттың шынайылығын

толық дәлелдемейді.

Сондықтан AI жасаған жауаптарды қажет жағдайда пайдаланушы өзі тексеруі тиіс.

## 10. Деректерді сақтау және транзакция

Сәтті генерациядан кейін Source және оған тиесілі Flashcard жазбалары сақталады.

Сақтау үшін Django-ның `transaction.atomic()` механизмі қолданылады.

Оның мақсаты — деректердің жартылай сақталуына жол бермеу.

Мысалы, үш карточканың екіншісін сақтау кезінде дерекқор қатесі пайда болса, транзакция кері қайтарылады.

Нәтижесінде:

- жаңа Source жазбасы сақталмайды;
- бірінші карточка да сақталмайды;
- жартылай карточкалар жиынтығы қалмайды.

Бұл механизм дерекқордағы мәліметтердің тұтастығын сақтауға көмектеседі.

## 11. Сақталған материалдар және URL

`study/urls.py` бойынша екі негізгі маршрут бар.

**Басты бет:**

```text
/
```

**Сақталған материалдың жеке беті:**

```text
/sources/<int:pk>/
```

Мысалы:

```text
http://127.0.0.1:8000/sources/1/
```

Мұндағы `1` — Source жазбасының ID нөмірі.

Нақты URL тек сол ID-ге сәйкес материал дерекқорда бар болғанда ашылады.

Материалдың жеке бетінде:

- тақырып;
- жасалған уақыт;
- сұрақтар;
- ашылып-жабылатын жауаптар;
- дәйексөздер;
- бастапқы оқу мәтіні

көрсетіледі.

Сұрақ бірден көрінеді. Жауап пен дәйексөз HTML-дің `<details>` және `<summary>` элементтері арқылы ашылады.

Бұл элементтерді пернетақтамен де басқаруға болады.

Django шаблонының автоматты HTML escaping механизмі пайдаланушы мәтінінің HTML код ретінде орындалу қаупін азайтады.

Сақталған материалдың detail беті карточкаларды қайта генерацияламайды, дерекқордан оқиды.

Жауаптың ашық немесе жабық күйі бөлек сақталмайды. Сондықтан F5 басқанда ол бастапқы жабық күйіне оралады.

## 12. Авторизация және деректерге қолжетімділік

Бұл нұсқада:

- пайдаланушы тіркелуі жоқ;
- login/logout механизмі жоқ;
- Source үшін owner өрісі жоқ;
- пайдаланушыға тиесілі материалдарды бөлу механизмі жоқ.

Сондықтан `/sources/<pk>/` адресін білетін адам сервер қолжетімді болса, сол материалды аша алады.

Жоба оқу және демонстрациялық мақсатқа арналған.

Құпия немесе жеке деректерді сақтайтын ашық сервис ретінде пайдаланбас бұрын авторизация мен қолжетімділікті шектеу механизмдерін қосу қажет.

## 13. Жобаны тексеру

Төмендегі командаларды студент өз компьютерінде орындайды.

Django конфигурациясын тексеру:

```bash
python manage.py check
```

Study қосымшасының тесттерін орындау:

```bash
python manage.py test study
```

Модель өзгерістеріне қатысты жасалмаған миграцияларды тексеру:

```bash
python manage.py makemigrations --check --dry-run
```

Бұл командалардың міндеттері әртүрлі.

`check` Django жүйелік конфигурациясындағы мәселелерді анықтайды.

`test study` автоматтандырылған тесттерді іске қосады. Django әдетте олар үшін бөлек тест дерекқорын пайдаланады.

`makemigrations --check --dry-run` модельдерге қатысты жаңа миграция қажет пе, соны тексереді.

### Автоматтандырылған тест сценарийлері

Жобаға дайындалған алты сценарий:

1. Дұрыс DEMO POST: redirect, бір Source және үш Flashcard.
2. Қысқа мәтін: генерация шақырылмайды.
3. Қате дәйексөз: бүкіл нәтиже қабылданбайды.
4. GenerationError: формадағы мәлімет сақталады, жаңа жазба жасалмайды.
5. Екінші карточкада DatabaseError: Source пен бірінші карточка rollback арқылы жойылады.
6. Detail бетіне екі GET: қайта генерация жоқ, дерекқор саны өзгермейді.

### Терминалдан алынған нәтиже

Бұрын берілген терминал қорытындысы:

```text
Found 6 test(s).
Creating test database for alias 'default'...
System check identified no issues (0 silenced).
......
----------------------------------------------------------------------
Ran 6 tests in 0.058s

OK
Destroying test database for alias 'default'...
```

Бұл қорытындыда 6 тест табылғаны және олардың барлығы сәтті аяқталғаны көрсетілген.

Алайда бұл нәтиже:

- LIVE режимінің нақты API арқылы тексерілгенін;
- барлық браузерлерде интерфейстің тексерілгенін;
- production ортада жүйенің жұмыс істейтінін

растамайды.

## 14. Қателер және оларды түсіндіру

### `no such table: study_source`

Бұл қате Django `study_source` кестесін SQLite дерекқорынан таба алмағанын білдіреді.

Көбінесе модельдер жасалғанымен, миграциялар дерекқорға қолданылмаған кезде кездеседі.

Тексеру үшін:

```bash
python manage.py migrate
```

Команданы студент өзі орындауы керек.

Егер қате қайталанса, қолданылып жатқан дерекқорды, миграциялардың жағдайын және Django settings конфигурациясын тексеру қажет.

### Генерация қатесі

DEMO режимінде дайын мысалдан басқа мәтін енгізілсе, генерация қабылданбайды.

LIVE режимінде API конфигурациясы, желілік байланыс немесе жауап форматы қате болуы мүмкін.

Қате кезінде жарамсыз нәтижені дерекқорға сақтамау қарастырылған.

### Дерекқорға сақтау қатесі

Source немесе Flashcard жазбаларын сақтау кезінде DatabaseError пайда болса, транзакция кері қайтарылады.

Формада жалпы қауіпсіз қате хабарламасы көрсетіледі.

Git командаларын және репозиторийге өзгерістерді жіберуді студент өзі орындайды.

## 16. Қорытынды

Teach Me — оқу материалын сұрақ-жауап карточкаларына айналдыратын Django жобасы.

Жүйе DEMO режимінде дайын үш карточкамен жұмыс істеуге, ал LIVE режимінде Gemini API арқылы жаңа материалдарды өңдеуге арналған.

Жобада деректерді сақтау, валидация, транзакция және сақталған карточкаларды қайта қарау мүмкіндіктері қарастырылған.

Негізгі артықшылығы — оқу материалын қайталауға ыңғайлы форматқа айналдыру.

Негізгі шектеулері — авторизацияның жоқтығы және дәйексөз тексеруінің жауаптың фактілік дұрыстығына толық кепілдік бермеуі.
